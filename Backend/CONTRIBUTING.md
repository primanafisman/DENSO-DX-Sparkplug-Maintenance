# Contributing

Use the approved design/plan and supplied governance audit. Keep route/controller/service/model boundaries; database changes are reviewed deployment scripts. Add a meaningful failing test before changing recognition/security/persistence behavior. Use Node22 and Python3.12; run Node/CV suites and architecture checks.

Do not commit credentials, database files, private photos, model weights, generated builds or runtime caches. Keep source internal/private until authorization from the company owner. Issue/PIC IDs, mentor approval and UAT signatures are supplied by actual responsible people; never fabricate them.

Requirements, API contracts, migration/provenance notes and changelog accompany behavior changes. Use source-only release tooling and inspect manifests. Public production deployment requires DX/security/database/Sonar/human UAT gates.
